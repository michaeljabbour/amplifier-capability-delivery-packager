# Shape, naming and separation

One approved local package is a tool call. Need N1 path 0 + N2 context 0 + N3 watched minutes 1 + N4 initiative 0 = 1: rung 1 Tool, engine None. H1 independent model verification 0,H2 specialists 0,H3 portability 1,H4 oversize 0: single tool. These are design judgments, not performance measurements.

G1 automatic byte/contract checks exist; semantic rights/accessibility are outside the promise. G2 new output, no overwrite, locally removable; G3 no outbound leg; G4 POSIX containment is bounded, no claim about arbitrary same-user attackers; G5 fixed file/byte caps, no model route; G6 operator owns actual permission. Unknown host gates do not grant more autonomy. R1 versioned preview/build/verify; R2 commodity stdlib engine; R3 one delivery job; R4 no credentials/identity system; R5 compare against manual allowlist ZIP plus manifest before claiming added value.

Keep the name Delivery Packager: a person wants a reviewable package, not an automatic delivery agent. Project Handoff explains state/decisions/next steps; this tool packages already approved files. ArticleCraft writes articles, Research assembles evidence, Taste judges form and Worth Using assesses usefulness. None is required. Optional handoffs are plain assets/JSON. No additional breakouts are justified by current evidence.

Market Fit target user/job is a hypothesis: a creator handing off editable and final assets without including working material. Pain, time saved, outside-user usefulness and return are unmeasured. Job/First value/Fit/Outcome/Trust/Return remain separate Claimed design hypotheses; local tests are not Seen or Repeated.
